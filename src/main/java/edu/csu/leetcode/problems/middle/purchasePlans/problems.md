# 两种商品恰好用完预算的方案数

分类：`middle`。标签：动态规划、完全背包、组合计数。自定义题，无力扣题号。

给定总金额 `n` 和两类商品的单价 `a`、`b`。每类商品数量不限，要求各至少购买一个，且总金额恰好用完，返回购买方案数。

每个方案是一个数量对 `(x, y)`，满足 `a * x + b * y == n`、`x >= 1`、`y >= 1`。购买顺序不影响方案；即使 `a == b`，两类商品仍按不同类型计数。

输入约定：`n` 为非负整数，`a`、`b` 为正整数，参数类型均为 `int`。不满足约定时抛出 `IllegalArgumentException`。本实现使用与剩余金额成正比的数组，适用于预算规模可容纳于内存的输入。

## 核心方法

```java
public long countPlans(int n, int a, int b)
```

## 示例

- `n = 14, a = 2, b = 3`：返回 `2`，方案为 `(4, 2)`、`(1, 4)`。
- `n = 5, a = 2, b = 3`：返回 `1`，方案为 `(1, 1)`。
- `n = 4, a = 2, b = 3`：返回 `0`，不足以各买一个。
- `n = 8, a = 2, b = 2`：返回 `3`，方案为 `(1, 3)`、`(2, 2)`、`(3, 1)`。

## 完全背包解法

先固定各购买一个，剩余预算 `remaining = n - a - b`。若为负数，返回 `0`。之后每类商品都允许购买零个或更多，转化为完全背包组合计数。

`dp[j]` 表示使用当前已处理的商品类型，恰好花费 `j` 的方案数。初始化 `dp[0] = 1`，表示额外什么都不买；其余状态初始化为 `0`。

外层依次处理商品 `a`、`b`，内层将金额从单价正序遍历到剩余预算，转移为 `dp[j] += dp[j - price]`。正序遍历使同一商品能重复购买；商品放在外层使每个数量组合只统计一次。两种商品即使价格相同也分别处理。

返回 `dp[remaining]`。时间复杂度 `O(remaining + 1)`，空间复杂度 `O(remaining + 1)`，不含预算不足时直接返回的情况。
